# Northwind Home Goods — DTC Sales Analytics Report

> **Sample project — synthetic data, not client work.** "Northwind Home Goods" is a fictional
> brand. All orders, customers and ad spend are generated by a seeded script. No real company,
> customer or platform account is involved.

## What it is

A complete, reproducible monthly performance report for a DTC e-commerce brand, built from an
18-month Shopify order export (USD + CAD) and Meta/Google daily ad spend. It covers revenue, orders,
AOV, repeat-customer rate, cohort retention, channel ROAS/CAC, top/bottom products, and five
recommendations. The brief is in [`BRIEF.md`](BRIEF.md).

The raw data is deliberately messy, the way real exports are. It includes duplicated order lines,
missing emails, negative quantities, timestamps in three formats and time zones, staff test orders,
voided orders, currency-code noise and a duplicated ad-spend export. Every fix is counted in a data-quality log.

## How to run (end to end)

Requires Python 3.9+.

```bash
cd portfolio/sales-analytics-report
python3 -m pip install --user pandas openpyxl matplotlib   # one-time
python3 src/run_all.py --with-sample-data                  # generate data -> clean -> analyze -> verify (~8 s)
```

To refresh from new exports (the ops-manager path), drop the files into `data/raw/` with the same
column layout and run:

```bash
python3 src/run_all.py        # clean -> analyze -> verify; stops with a non-zero exit if any QA check fails
```

You can also run each step on its own: `python3 src/generate_data.py`, `python3 src/clean.py`, `python3 src/analyze.py`,
`python3 src/verify.py --verbose`.

## QA results

`src/verify.py` is an **independent code path**. It uses only the standard library (`csv`,
`datetime`, `zoneinfo`; no pandas), shares no code with `clean.py` or `analyze.py`, and re-applies
the cleaning rules from the raw CSVs. It then compares its results with the **values written into
the workbook** and the **text of the executive summary**.

The latest run passed **123 of 123 checks** (`deliverables/qa_report.txt`). The checks cover:

- all 18 Summary KPIs match the raw recompute (tolerance: 1e-6 relative or $0.01)
- per month: net revenue, orders, repeat rate and ad spend all match. No month has negative revenue. Months sum to the headline totals, and AOV = revenue ÷ orders
- cohorts: sizes sum to identified customers (7,682), M0 = 100%, the grid has one column per month offset, every cell matches the recompute and lies in [0, 1], and no count exceeds its cohort size
- channels: ROAS = revenue ÷ spend and CAC = spend ÷ new customers on every row, including all 36 paid channel-month rows. Revenue, spend and new customers sum to the totals. Channels with no spend show a blank ROAS, not a divide-by-zero
- products: each SKU matches the recompute, nothing is negative, and products sum to the total
- the data-quality log's output row count matches the independent recompute
- the executive summary: every number in the headline table, and all 18 supporting figures, appear verbatim and match

**Mutation test:** I edited a copy of the workbook (Meta ROAS +5%, one month's revenue +$500) and
ran `VERIFY_XLSX=<copy> python3 src/verify.py`. It failed 4 checks, so the QA does catch tampering.

**Fix cycles:** 1. `verify.py` passed on its first run. Inspecting the workbook by hand then
showed that the cohort grid dropped the +17 column because no customer had ordered at that offset.
I fixed this (offsets are now reindexed with zeros), added a regression check, and QA passed again.
Separately, there were two rounds of chart-legibility fixes after viewing the PNGs: duplicate
"2x" y-tick labels on the ROAS chart, a truncated title and crowded ticks on the product chart, an
empty cohort row, and break-even precision aligned with the summary.

## Limitations

- **Synthetic data.** The patterns (Meta CAC drift, the refund-heavy duvet, Bedding-led retention,
  deep BFCM discounting) were planted by the generator. The analysis detects them; it does not prove
  that real brands behave this way.
- **Last-click attribution** from the Shopify source field. The paid-channel ROAS shown is not
  incrementality. Recommendation 1 proposes a geo holdout for exactly this reason.
- **No history before Apr 2025.** Every customer's first order falls in the window, so "new
  customers" equals "identified customers". Early months understate repeat rates.
- **Customer identity is email only.** There is no cross-device or household matching. Orders with
  no email count toward revenue but not toward customer metrics.
- **COGS is a static unit cost per SKU.** Refunded units are assumed not restocked, which is
  conservative. Shipping, tax, payment fees and returns logistics are excluded.
- **FX:** a single monthly CAD→USD rate, not the daily settlement rate.
- **Net revenue precision:** clean.py rounds per-line USD values to 4 dp. Over 20k lines, the
  workbook total and the raw recompute differ by about $0.02, which is within QA tolerance.
- **Refresh is script-driven, not Power Query.** The workbook is regenerated on each run, so manual
  edits are overwritten. Only the Monthly and Cohort total rows are live Excel formulas.
- I could not render the workbook in Excel or LibreOffice in this environment. Its structure,
  conditional-format ranges and embedded images were checked with openpyxl, and the charts were
  inspected visually as PNGs.
